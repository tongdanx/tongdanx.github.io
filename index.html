从寄存器到标准库：STM32 GPIO点亮LED的两种方式

这是我 STM32 系列笔记的第2篇文章。

上一篇介绍了如何建立模板，这一篇基于STM32工程模板：从零搭建你的代码地基中搭建的工程模板实现GPIO点亮LED，并对比寄存器与标准库两种开发方式。

硬件原理

PA0控制LED，低电平驱动

LED负极接PA0口，LED正极接3.3V

当PA0低电平时，LED正负极有压降差，LED正向导通，灯亮

基于寄存器开发

打开时钟

在系统结构图里面，GPIO是挂在APB2上的，所以时钟配置应该选在APB2总线

APB1和APB2的区别：APB1操作速度限于36MHz，APB2操作于全速(最高72MHz)。

查询数据手册：APB2ENR的位2控制PA口，所以位2设置为1，也就是1 << 2，所以是

配置模式

推挽输出，50MHz

LED接在PA0口，属于低位，所以应该用GPIO的CRL寄存器

查询数据手册：CRL的低四位设置为0b0011也就是0x03时，模式为50MHz的推挽输出

设置电平

低电平亮灯

查询数据手册：GPIO的BSRR寄存器位16为1时，可以清除PA0口的电平，使之为低电平，也就是0x10000

因为 BSRR 是只写寄存器，读它没有意义，所以直接赋值

BSRR 写入 0 无效果，所以不需要先清零

基于标准库开发

时钟使能–RCC_APB2PeriphClockCmd

第一个参数：需要操作的时钟外设

第二个参数：状态

初始化GPIO–GPIO_Init

第一个参数：需要初始化的GPIO

第二个参数：GPIO的配置结构体–GPIO_InitTypeDef

GPIO_InitTypeDef

GPIO_Mode： 配置模式

GPIO_Pin ：GPIO口

GPIO_Speed ：配置速度

设置GPIO值为低电平–GPIO_ResetBits

第一个参数：GPIO

第二个参数：需要设置为低电平的GPIO口

思考总结

问题

我在实验过程中，发现两种模式下屏蔽掉设置电平步骤的代码后，小灯居然可以正常亮，按道理来说

电平未设置为低电平，小灯应该是不亮的

猜想

然后我就研究数据手册，发现GPIO的ODR寄存器的复位值是0，意味着什么？

意味着在复位状态下，输出模式时，GPIO口输出低电平，所以在未设置电平的情况下，小灯也是可以亮的

验证

为了验证该猜想是否正确，我就在设置电平前把GPIO的ODR寄存器的低16位每一位都设置为1了，然后未进行后续的PA0口电平设置，发现小灯不亮，后续再单独对PA0口进行电平设置，将其设置为低电平后，小灯就正常亮了，所以该猜想成立

此处之所以是在设置电平前设置GPIO的ODR的值，是因为ODR 的值要真正驱动到引脚上，前提是时钟已使能、模式已配置为输出

结论

因为GPIO的ODR寄存器复位值是0，输出模式下，ODR的复位值被驱动到引脚，所以在未设置PA0口为低电平时，小灯能正常亮

两种方式对比

对比维度 基于寄存器开发 基于标准库开发
代码量 少，但是需要手动计算寄存器的值 多，但是容易懂
可读性 差，需要阅读数据手册 好，函数名称可以很直观的看出功能
上手难度 高 低
对硬件的理解 深入 浅
适合场景 学习原理，理解硬件 项目开发，快速实现

STM32工程模板：从零搭建你的代码地基

这是我 STM 32 系列笔记的第1篇文章。后续所有代码均基于本文搭建的工程模板。

为什么需要工程模板？

学习 STM32 的过程中，每开始一个新实验（比如 GPIO、USART、定时器），都需要重复做同样的事情：新建工程、拷贝固件库、配置环境。这个过程繁琐且容易出错。

如果每次都从头开始，不仅浪费时间，还容易因为漏掉某个文件而导致编译失败。所以，提前搭建好一个“空模板”，后续所有实验都从这个模板拷贝，是高效开发的关键。

下面提供两种模板：标准库模板适用于日常项目开发，代码可读性高；寄存器模板更精简，适合用来学习底层原理。你可以根据自己的学习阶段和需求来选择。

准备工作

在开始之前，请确保以下软件或文件存在：

软件或文件 说明
Keil MDK STM32 的主流开发环境（本文使用 Keil uVision5）
STM32F10x_StdPeriph_Lib_V3.5.0 固件库，我的是江协科技下载的

方案一：基于标准库的工程模板

工程目录

在电脑上新建一个文件夹，命名为01_stm32_model，这是我的工程根目录

然后再新建一个文件夹，命名为public，这是我放STM32的核心文件的文件夹

然后再建子目录

01_stm32_model/
├── user/ # 用户代码（main.c 等）
├── DebugConfig/ # Keil 自动生成，无需手动创建
├── Listings/ # Keil 自动生成，无需手动创建
└── Objects/ # Keil 自动生成，无需手动创建

public/
├── inc/ # 标准外设驱动的库函数的头文件
├── project/ # 配置库文件的头文件的包含关系的文件、用来参数检查的函数的定义的文件、存放中断函数的文件
├── src/ # 标准外设驱动的库函数的源文件
└── start/ # 启动文件、内核寄存器描述文件、外设寄存器描述文件、配置时钟文件

拷贝核心文件

源文件路径（在固件库中） 复制到工程目录
.\STM32F10x_StdPeriph_Lib_V3.5.0\Libraries\CMSIS\CM3\CoreSupport\ 下的内核寄存器描述文件 start/
.\STM32F10x_StdPeriph_Lib_V3.5.0\Libraries\CMSIS\CM3\DeviceSupport\ST\STM32F10x\startup\arm\ 下的启动文件 start/
.\STM32F10x_StdPeriph_Lib_V3.5.0\Libraries\CMSIS\CM3\DeviceSupport\ST\STM32F10x\ 下的外设寄存器描述文件以及配置时钟文件 start/
.\STM32F10x_StdPeriph_Lib_V3.5.0\Libraries\STM32F10x_StdPeriph_Driver\inc\ 下的标准外设驱动的库函数的头文件 inc/
.\STM32F10x_StdPeriph_Lib_V3.5.0\Libraries\STM32F10x_StdPeriph_Driver\src\ 下的标准外设驱动的库函数的源文件 src/
.\STM32F10x_StdPeriph_Lib_V3.5.0\Project\STM32F10x_StdPeriph_Template\ 下的配置库文件的头文件的包含关系的文件、用来参数检查的函数的定义的文件、存放中断函数的文件 project/

创建main.c文件

Keil配置

  1. 打开 Keil，点击 Project → New uVision Project，选择 01_stm32_model/ 目录，工程名为 01_stm32_model。

  2. 芯片选择 STM32F103C8（根据你的实际芯片型号选择）。

  3. 点击工程管理器（Manage Project Items），添加以下组：

    • user：添加 main.c

    • start：添加public/start/下的启动文件以及所有的.c和.h文件

    • inc：添加 public/inc/ 下的所有 .h 文件

    • src：添加 public/src 下的所有 .c 文件

    • project：添加 public/project 下的所有 .c 和.h文件

  4. 点击魔术棒（Options for Target），在 C/C++ 选项卡中：

    • 添加宏定义：USE_STDPERIPH_DRIVER

    • 添加头文件路径：public/start/、public/inc/、public/project/

编译测试

点击编译按钮，如果没有报错，说明工程模板搭建成功。
